# Recitation audio

Spoken recitation for the reader's bottom player
(`src/components/AudioPlayer.astro`). Each chalisa has two files here:

- `<slug>.mp3` — the full spoken paath
- `<slug>.json` — start/end time of every verse, used to highlight the
  verse being recited and to let readers tap a verse to jump to it

The slug matches the JSON filename in `src/content/chalisas/`.

## Generating a recitation

The audio is generated by us from the Devanagari text with an ElevenLabs
Hindi voice, so it is our own recording rather than a copy of any
commercial rendition.

1. On a **paid** ElevenLabs plan (required for commercial use of the
   output), pick a stock or Voice Library Hindi voice — not a clone of a
   known singer — and copy its voice ID.
2. Create `.env` in the project root (it is gitignored):

   ```
   ELEVENLABS_API_KEY=...
   ELEVENLABS_VOICE_ID=...
   # optional, defaults to eleven_multilingual_v2
   # ELEVENLABS_MODEL_ID=eleven_multilingual_v2
   ```

3. Make sure `ffmpeg` and `ffprobe` are installed (`brew install ffmpeg`).
4. Run:

   ```
   npm run audio -- hanuman
   ```

   Each verse is sent to the voice as one request (approved "variant A"
   settings: stability 0.5, style 0.35, speed 0.9) and cached in
   `.audio-cache/`. A pause follows the verse (0.9 s after a doha, 0.45 s
   after a chaupai). The danda stays in the text so the voice pauses at
   phrase ends.

5. Listen to the whole file. If a line is mispronounced (watch Awadhi
   words), regenerate just that verse by its index in the JSON `verses`
   array, then the file is rebuilt from cache:

   ```
   npm run audio -- hanuman --redo 12
   ```

   Editing a verse's `hi` text also regenerates only that verse.

6. In that chalisa's JSON, set:

   ```json
   "audioUrl": "/audio/hanuman.mp3",
   "audioAttribution": "Recitation"
   ```

The player enables itself once `audioUrl` is set, and SEO descriptions
start mentioning audio for that chalisa only. The dock shows the translated
word “Recitation” (`audio.recitation` in `src/i18n/ui.ts`), not this field.
If the file is missing, the player falls back to a disabled "coming soon" state.

## Licensing bar

Only host audio we are allowed to host: recitations we generate as above,
recordings we own or commissioned, or verified public-domain / CC0
recordings. Do **not** self-host commercial devotional recordings
(T-Series, Tips, etc.), even if a re-uploader has tagged them "CC".
Always record the source in `audioAttribution`.
